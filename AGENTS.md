- Sensitive Suite fields (DOB, ID/passport, tax, bank) are encrypted by database triggers into *_enc columns with masked copies; read full values only via suite_reveal_pii (logged). Why: plaintext never rests in client tables.
- Permanent account bans live in the admin-readable account_email_bans table and are enforced by an Auth lifecycle trigger; account deletion uses the Auth admin API. Why: deleting an identity must not allow its banned email to register again or require direct edits to managed Auth tables.
- The Suite Screening route renders the shared Screening console inside Suite access/module gates, not the standalone workspace or basic search page. Why: consolidation must retain existing screening cases and controls without automatic trial activation.
- Suite team is managed only via suite_* team RPCs on suite_org_members (product_members kept in sync by trigger); screening_audit_events are mirrored into suite_audit_log, read via suite_audit_feed. Why: one team list and one immutable audit trail per company.
- Admin notification actions use a shared URL resolver; form-submission actions open a record-specific enquiry dialog on the dashboard through existing authenticated reads. Why: historical dashboard links must open the matching enquiry instead of silently reloading the same page.
- MRZ Document Check validity is decided only by the deterministic ICAO 9303 parser in src/lib/suite/mrz.ts; the mrz-ocr function only transcribes lines, and results are saved via suite_record_mrz_check (raw MRZ encrypted, audit mirrored). Why: no AI decides validity and no full MRZ rests in plaintext.
- The fallback <meta name="description"> in index.html carries data-rh="true" so each page's own Helmet description replaces it; sitewide og:* fallbacks stay untagged for social crawlers. Why: a second, generic description on every page makes search engines write their own snippet instead of the page's.
- Suite organisations are created only by platform admins, admin-approved quotes, paid checkout, or enterprise demo claims passing supabase/functions/_shared/orgCreationPolicy.ts (company email + real company name); a DB trigger rejects personal-email-domain names. Why: Academy and self-serve signups must never spawn tenants.
